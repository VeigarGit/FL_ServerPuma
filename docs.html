Start with a simple baseline

FL_ServerPuma contains a central server, local training clients, dataset partitioning tools, and experiment scripts. The studies behind the project investigate adaptive pruning in heterogeneous federated learning.

The commands below start a small MNIST experiment with two clients and no pruning. Use this baseline to check your environment before exploring more complex configurations.

Code and papers serve different purposes. This guide describes the repository’s current entry points. The OPALA and PUMA papers use their own experiment settings; the quick start is not a reproduction of those benchmarks.

1. Install the environment

Install uv and tmux for local execution. The project specifies Python 3.11 and uses a uv lockfile.

git clone https://github.com/VeigarGit/FL_ServerPuma.git
cd FL_ServerPuma
uv sync

For containerized execution, install Docker with Compose and use an NVIDIA GPU environment compatible with the repository’s Docker configuration. Traffic shaping additionally requires the docker-tc service described in the repository README.

2. Prepare client data

Generate the dataset partitions before starting the server and clients. This example requests a non-IID Dirichlet partition of MNIST.

uv run python src/dataset/generate_MNIST.py noniid - dir

For CIFAR-10, replace the generator with generate_Cifar10.py. For CIFAR-100, use generate_Cifar100.py.

Check the generator’s num_clients setting before running. The number of partitions must cover every client in your experiment. The paper’s Dirichlet concentration is an experiment setting, not necessarily the generator’s current default.

3. Run an experiment

cd src/system
bash run.sh --dataset MNIST --clients 2 --rounds 5 --prune 0 --ala 1

# Open the server and client terminal windows
tmux attach -t fl_puma

Add --cpu to run the local baseline on the CPU. Use Ctrl+b, then n or p to move between tmux windows.

Inspect the available options

bash run.sh --help
# From the repository root
cd docker
uv run python generate_compose.py --clients 2 --dataset MNIST --rounds 5 --prune 0 --ala 1

docker compose --project-directory .. -f docker-compose.generated.yml up --build

# After the experiment
docker compose --project-directory .. -f docker-compose.generated.yml down

The generated configuration exposes the server on port 9000 and mounts the dataset and results directories. Its GPU reservations assume an NVIDIA Docker environment.

For pretrained models, prepare the Hugging Face model cache or explicitly enable online access in the container environment. A new cache volume starts empty.

Configure your experiment

These are common options for src/system/run.sh. Save the full command, code revision, seeds, and dataset partition settings with your results.

OptionPurposeExample
--clientsNumber of training clients8
--roundsCommunication rounds25
--datasetPrepared dataset nameCifar10
--modelModel familycnn, clip, slm
--pruneCNN adaptive pruning1 on / 0 off
--alaAggregation mode0 FedALA / 1 FedAvg
--num-classesClassifier output size10 for CIFAR-10
--strategyAdapter training strategylora, sora_with_schedule
--exp-nameResults directory namecifar10_baseline

Not every execution mode supports every model and option combination. Check the relevant entry point and configuration file when moving beyond the baseline.

Models and research extensions

ComponentWhere to exploreFocus
CNNsrc/system/model.pyBaseline training and structural pruning
CLIP adapterssrc/system/lora_clip/LoRA, SoRA, and partial calibration
SLM adapterssrc/system/lora_slm/Multimodal model adaptation
LHDQsrc/utils/lhdq.pyDelta compression experiments
Vehicular learningsrc/sumo_adapter/SUMO-orchestrated client encounters

CLIP, SLM, delta compression, and vehicular experiments extend the current repository beyond the CNN evaluations reported in the two papers. The paper benchmarks should not be interpreted as measured results for these extensions.

Find your results

Experiment outputs are written below src/results/<experiment_name>/. HDF5 files contain accuracy and loss series, timing measurements, and communication statistics. Saved model weights are optional.

FL_ServerPuma/
├── src/
│   ├── dataset/          Dataset generation and partitions
│   ├── system/           Server, clients, models and training
│   ├── utils/            Transport, aggregation and compression
│   ├── sumo_adapter/     Vehicular simulation orchestration
│   └── results/          Experiment outputs
├── docker/               Container setup and Compose generator
├── pyproject.toml        Environment configuration
└── uv.lock               Resolved Python dependencies

For the published study configurations and reported values, visit Benchmarks. To discuss reproducibility or report an issue, use the GitHub issue tracker.
